## 1. 目标、范围与非目标

### 1.1 视觉目标

在不改动模拟层数值、不破坏现有测试契约的前提下，把"技术 Demo 观感"提升到"有美术的游戏"：

1. **第一眼**：选人立绘、局内模型、技能特效、UI 主色属于同一个角色/同一个世界观。
2. **默认镜头（zoom 21）**：英雄、小兵、野怪、塔、墙的剪影和阵营能一眼分辨。
3. **每个技能有签名**：不靠文字，靠图标 + 颜色 + 形状 + 命中残留就能认出是谁放了什么。
4. **场景有层次**：河道、野区、兵线、基地四个区域有各自的材质/道具/环境生命感。
5. **UI 有资产感**：不是纯色圆角面板 + 矢量符号，而是成套的图标、边框、状态、结算展示。

### 1.3 非目标（明确不做）

- **不改玩法数值**：伤害、经济、刷野、塔序、兵线一律不动。视觉工作只读快照、只发表现事件。
- **不在可玩区抬地形**：`test_terrain.test_playable_area_stays_perfectly_flat` 是硬契约；高地/台地只能在不可走区域做"视觉抬升"。
- **不在可玩区放树**：`test_map_presentation.test_map_scenery_ships_no_trees` 已把树挡在门外；用岩石、兽骨、残柱、芦苇、藤蔓替代。
- **不追王者写实**：GL Compatibility + 移动端 0.72× + 21m 镜头，追写实是负收益。目标是"风格化、剪影优先、2D 资产高清"。
- **不做皮肤系统**：P2 再议；P0/P1 只预留接口，不排期。
- **不一次性替换所有模型**：P0 用调参与程序化配件解决"出戏"，P1 才评估定制模型。

### 1.4 目标风格（一句话）

> **东方幻想 + 程序化低模 + 高清 2D 图标/立绘**：3D 负责剪影、阵营、体量；2D 负责细节、质感、记忆点；特效负责"技能签名"。

三条视觉支柱：

1. **剪影优先**：21m 机位下先看清"是谁、哪边、多大"，再谈贴图。
2. **区域编码**：蓝/红半场、河道、野区、兵线、基地各有一套颜色/材质/道具语言。
3. **技能签名**：每个技能至少有一个"只有它有"的形状/颜色/残留/节奏。

## 2. 基线、依赖与锁定契约

### 2.1 当前基线

- 5 英雄 / 8 装备 / 12 野点 + 2 首领 + 2 河道之灵 / 10 草丛 / 7 种野怪形态。
- 3D：2 套英雄身体、2 套小兵、1 块 162 面 `Rock.glb`、程序化塔/地形/草/灌木。
- 2D：5 张 1024² 立绘、5 段 OGV、8 张 256² 装备图标、5 族矢量技能图标。
- 渲染：GL Compatibility；Bloom + 雾 + Filmic；无 SSAO/SSR；移动端 3D 0.72×、阴影 36m。
- 测试基线：**以当次运行为准**，不把数字写死。

```cmd
godot --headless --path godot --script res://tests/run_tests.gd
```

### 2.2 锁定契约（不可被视觉改动破坏）

| 契约 | 测试 / 文件 | 视觉工作必须遵守 |
| --- | --- | --- |
| 可玩区严格平地 | `test_terrain.test_playable_area_stays_perfectly_flat` | 高地/台地只能放在 `PLAY_HALF` 之外 |
| 不放树 | `test_map_presentation.test_map_scenery_ships_no_trees` | 用非树道具替代 |
| 塔细高、不挡人 | `test_map_presentation.test_tower_model_is_slim_and_tall`（高 >8.2m、宽 <3.0m、宽高比 >2.8） | 塔的装饰只能往"高/细"方向加 |
| 墙体尺寸与碰撞同源 | `test_wall_look.test_every_jungle_wall_gets_a_named_barrier_with_sim_dimensions` | 视觉不能比碰撞厚/宽 |
| 岩脊不伸进贴墙位 | `test_wall_look.test_wall_ridge_rocks_stay_inside_the_collision_footprint` | 新岩石变体也要过量测 |
| 边界墙不挡视线 | `test_wall_occlusion.test_wall_never_hides_the_hero_at_the_walkable_limit` | 抬高墙必须重算 `WALL_TOP` 并过测试 |
| 野怪体型贴合碰撞 | `test_monster_forms.test_form_footprint_tracks_the_collision_radius` | 加配件不能把包围盒撑爆 |
| 野怪材质复用 | `test_monster_forms.test_monster_view_reuses_shared_materials_across_spawns` | 不能用"给每只怪复制材质"做闪白 |
| 英雄血条契约 | `test_hero_readout` | 加配件/头饰不能挡血条 |
| HUD 分区不重叠 | `test_hud_layout` / `test_touch_hud_grouping` | 新增图标行必须重新量最小尺寸 |
| 技能图标矢量兜底 | `test_skill_glyph` | 贴图图标必须保留矢量 fallback |
| 装备图标全覆盖 | `test_item_icons` | 新增装备必须同时加图标 |
| 技能特效必达 | `test_skill_vfx` | 新 `kind` 必须有配方，`arena` 必须分发 |
| 输入/实体/事件白名单 | `test_net_protocol`、`net/net_protocol.gd` | 新增事件键必须进 `_sanitize_event`；新增实体字段必须过 6 处链路 |

> **改契约 = 一次显式决策**：如果确实需要突破（例如抬高城墙），必须在同一提交里更新测试、注释与差距文档，并在验收证据里记录"为什么旧门限不再适用"。**不允许**把测试改松来让实现通过。

### 2.3 并发与工作区纪律

- 开工前 `git status --porcelain`；不要在有别人未提交改动时大范围重排文件。
- 视觉任务尽量**只碰表现层文件**；必须碰 `sim/` 时（如 `monster_attack` 事件）单独提交、单独验收。
- 截图落 `godot/shots/`（不入库）；验收证据的 README 记录文件名与命令。
- 不在战斗路径新增 `.new()` / `queue_free()`；新特效必须进池。

## 3. 工作分解（WBS）

### 3.4 W3 · 野怪与小兵

#### MON-01 野怪攻击前倾 / 受击缩身 / 闪白（P0）

这是本次唯一需要动 `sim/` 的视觉任务，必须走完整链路：

1. **sim 发事件**：`_update_monsters()` 在真正造成伤害的那一帧发 `monster_attack`：
   ```gdscript
   _emit("monster_attack", {
       "source": entity.id, "name": entity.get("name", "野怪"),
       "monster_type": str(entity.get("monster_type", "wolf")),
       "x": ..., "y": ..., "target_x": ..., "target_y": ...,
   })
   ```
2. **协议白名单**：`net/net_protocol.gd::_sanitize_event` 增加 `monster_type`（其余键已存在）；`test_net_protocol` 加一条"monster_attack 过白名单"。
3. **arena 分发**：`_process_events()` 增加 `"monster_attack"` 分支 → 找到对应 `UnitVisual` → `play_monster_attack()`。
4. **view 表现**：`UnitVisual` 新增 `play_monster_attack()`（前倾 + 前冲 0.12s + 回弹）、`play_hit()` 对 monster 生效（缩身 + 闪白 0.08s）；程序化形态没有骨骼，用 `model_root` 的位移/缩放/旋转叠加，**不要覆盖 `_capture_model_rest_pose`**。
5. **闪白实现**：优先给 `monster_kit` 的材质换 `ShaderMaterial` + `instance uniform float hit_flash`，用 `GeometryInstance3D.set_instance_shader_parameter` 逐实例闪白；共享材质对象不变（保住 `test_monster_view_reuses_shared_materials_across_spawns`）。若 GL Compatibility 下实例 uniform 不可用，退回"胸口加一个 0.08s 的加色球"（也走池/预建节点）。
6. **受击接线**：`_handle_hit_event()` 目前只对 `target_type == "hero"` 调 `view.play_hit()`；扩展到 `monster` 与 `minion`。

  3. 程序化 `ArrayMesh` 生成 1–2 种低模岩块（不同棱角/长宽比）。
- 每个变体保持：共享 `rock_wall` 材质、`MultiMesh` 批次、`rock_specs` meta、阴影策略、墙脚植被（草丛/藤蔓）。
- 测试：扩展 `test_wall_look.gd`：每个变体都存在、高度变化 >0.25m、不伸进贴墙位；`test_wall_ends` / `test_jungle_walls` 保持；新增 `test_wall_variants.gd` 断言 ≥3 种轮廓。
- 验收：**A8**：同一段墙近景/俯视截图；不再像同一块石头复制；性能不超预算。

#### WALL-02 ~ WALL-04（P1）

## 4. 数据流与接口约定

### 4.1 三条铁律

1. **UI/View 只读快照**：不直接改 `hp`/`gold`/`inventory`；点击只发意图。
2. **表现事件走白名单**：新增事件（如 `monster_attack`）必须过 `_sanitize_event`；新增实体字段必须过 `04-combat-chain.md` 的 6 处清单。
3. **战斗中零分配**：所有新特效/图标/残骸在加载或池初始化时创建；战斗路径只借/还/改参数。

### 4.2 能不加字段就不加

| 需求 | 现有字段 | 结论 |
| --- | --- | --- |
| 红/蓝 BUFF 图标 | `buff_red_timer` / `buff_blue_timer` | 不加 |
| 护盾泡 | `shield` | 不加 |
| 减速/加速 | `slow_timer` / `haste_timer` | 不加 |
| 装备格 | `inventory` | 不加 |
| 小兵类型外观 | `minion_type` | 不加 |
| 野怪 BUFF/首领 | `buff_type` / `objective` / `objective_id` | 不加 |
| 塔摧毁状态 | `alive` + `tower_destroyed` 事件 | 不加 |
| 野怪攻击动作 | **无事件** | 新增 `monster_attack` 事件（唯一 sim 改动） |

### 4.3 新增 `monster_attack` 的完整链路（照抄清单）

1. `sim/match_sim.gd::_update_monsters()` 发事件；
2. `net/net_protocol.gd::_sanitize_event` 加 `monster_type`（其余键已在名单）；
3. `scripts/game/arena.gd::_process_events()` 加分支；
4. `scripts/game/unit_visual.gd` 加 `play_monster_attack()`；
5. `tests/test_net_protocol.gd` 加白名单断言；
6. `tests/test_monster_reactions.gd` 加端到端断言。

> 少任何一步 = 单机有、联机无，或测试绿、游戏里看不到。

### 4.4 资产接口

- 图标：`SkillIcon.texture_for(hero_type, slot, kind, spell) -> Texture2D`；缺失返回 `null`，调用方回落矢量。
- 状态：`GameTheme.status_icon(status_id, size) -> Texture2D`；缺失回落到纯色块 + 首字。
- VFX：`FxTextures.get(name) -> Texture2D`；缺失回落到白圆点，不允许 `load()` 返回 null 后崩溃。
- 9-slice：`GameTheme.frame(name) -> StyleBoxTexture`；缺失回落到现有 `StyleBoxFlat`。

| Draw call | 基线 + 预算（P0 ≤ +30；P1 ≤ +80，M0 量基线后校准） | 同左 | 渲染调试/引擎 monitor |
| 纹理内存 | P0 ≤ +16MB；P1 ≤ +64MB（M0 量基线后校准） | 同左 | 资产统计 + 真机 |
| 3D 分辨率 | — | 保持 0.72× 或按机型分级 | `project.godot` / 设置 |

### 7.7 联机验收（G5）

只对"新增事件/字段"的任务强制：

- `monster_attack` 必须在 `_sanitize_event` 白名单里；
- 主机与客机在同一局都看到野怪前倾/闪白；
- 客机不因事件缺字段报错；
- `test_net_protocol` 新增断言；
- 联机截图/日志归档。

> 纯 UI/2D 任务（图标、商店、MVP）不改协议，交付说明里要写"仅本地表现，联机无差异"。

### 7.8 真机验收（G8）

- 改 Android 可见行为（UI/视频/输入/打包）后**重导 APK**；旧包不算。
- `cd godot && python tools/device_checks.py`，无 FAIL；`ENV-01` / `PHASE-*` SKIP 不算通过。
- 人工用例：触屏 HUD、技能图标、商店、5v5 团战、野区、塔毁、结算。
- `report.json` 与设备型号/系统版本记入证据 README。

### 7.9 验收流程与签字

1. **开发自测**：G1/G2/G3/G6 先过，提交证据。
2. **视觉自检**：按 S1–S10 截图，和"改前"并排；填 §7.5 表。
3. **交叉复核**：至少 1 名非作者（或隔天自审）按 S1–S10 复核；只看截图，不看代码。
4. **验收会**：逐项过 §7.3/§7.4 矩阵；未过项不得口头"下次补"。
5. **签字**：在 `docs/acceptance-evidence/visual-<milestone>-<date>/README.md` 写：
   - 基线/改动后用例数；
   - 通过项 / 未通过项；
   - 证据文件清单；
   - 签字人 + 日期 + commit hash。

### 7.10 拒绝条件（出现任一，直接不通过）

- 测试末行不是 `FAILED: 0`，或新用例里有 `ERROR:`。
- 新模块/新图标只在 `tests/` 或 `tools/` 里被引用，生产代码 0 引用。
- 画面只在"画廊工具"里好看，真实对局看不到（未接线）。
- 单机有、联机无（新事件未进白名单）。
- 为过测试而放宽门限（例如把塔加宽、把地形抬高、把 HUD 分区改小）。
- 截图是旧的、或没有改前/改后对比。
- 移动端低于 30fps，或战斗中新增分配导致卡顿。
- 新资产无来源/授权记录。
- 为了"更华丽"把中路视野糊住、血条挡住、技能图标不可读。

| 风险 | 概率 | 影响 | 对策 |
| --- | --- | --- | --- |

| 21m 镜头看不清细节 | 高 | 投入浪费 | 先做剪影/主色；细节资产只在高关注点（选人/商店/近景）加 |
| 抬高城墙挡英雄 | 中 | 可玩性事故 | 只用不可走区域；同步 `WALL_TOP` + `test_wall_occlusion` |

| 并发会话覆盖 | 中 | 丢工作 | 开工/收工 `git status`；共享文件小步提交；不 stash 别人文件 |
| 范围蔓延到皮肤/英雄数量 | 高 | 永远做不完 | P0/P1 明确不做；P2 另立文档 |
