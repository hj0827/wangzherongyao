# 烽火峡谷 · 游戏架构与代码分层规约 (Architecture Specification)

> **版本**：1.0.0  
> **基线引擎**：Godot 4.7+ (GL Compatibility / Mobile)  
> **适用范围**：工程内所有 GDScript 逻辑开发、资源组织及后续功能扩展。

---

## 1. 架构设计哲学与核心原则

MOBA（多人在线战术竞技）具有三个极其严苛的技术特征：
1. **绝对确定性（Deterministic Core）**：普攻判定、技能命中、冷却倒计时、泉水恢复、小兵 AI 行为必须在 PC、手机、专用服务器以及无头单测环境中产出 **100% 一致** 的计算结果。
2. **高频渲染解耦（Smooth View）**：逻辑刷新率（固定 30Hz）与渲染帧率（60~120fps）天然分离。视觉表现必须基于状态快照做平滑插值（Lerp / Jitter Buffer），绝不能直接把逻辑死锁在渲染帧上。
3. **零垃圾回收抖动（Zero GC Jitter）**：5v5 团战数十个单位交火时，高频对象必须预分配，杜绝主线程实时分配带来的真机卡顿。

基于上述特征，本项目确立 **「Core-View 严格解耦的分层领域架构」（Clean Game Architecture）** 为最高准则。

```
       +-------------------------------------------------------+
       |                     app/ (应用壳)                      |
       |             全局生命周期、场景流转、着色器预热             |
       +-------------------------------------------------------+
              |                                    |
              v                                    v
       +---------------+                  +--------------------+
       |   ui/ (2D)    |                  |    view/ (3D)      |
       |  HUD、触控摇杆 |                  |  单位装配、平滑插值  |
       |  技能轮盘、弹窗 |                  |  指示环、受击特效   |
       +---------------+                  +--------------------+
              |                                    ^
       (发送用户意图)                               | (读取只读快照)
              v                                    |
+----------------------------------------------------------------------+
|                           core/ (逻辑核)                             |
|          纯 GDScript 类（绝不继承 Node / 零视觉 / 确定性计算）          |
|  sim (仿真) | combat (战斗) | skills (技能) | entities (实体) | map (数据) |
+----------------------------------------------------------------------+
              ^
              | (驱动状态同步)
+----------------------------------------------------------------------+
|                           net/ (网络层)                              |
|           客户端 Jitter Buffer、服务端权威广播、消息协议、局域网发现        |
+----------------------------------------------------------------------+
              ^
              |
+----------------------------------------------------------------------+
|                          infra/ (基础设施)                           |
|               全局对象池 (Pool)、统一输入抽象、音频管理器               |
+----------------------------------------------------------------------+
```

## 2. 六大核心层级与目录细化标准

所有游戏运行时源码必须严格按功能归入以下 6 大目录中，禁止在非约定路径散落代码：

### 2.1 `godot/scripts/core/`（领域逻辑核）
* **定位**：纯数据与算法计算层，与渲染完全隔离。
* **继承规则**：**严禁** `extends Node`、`Node3D` 或 `Control`；所有类均为纯 `RefCounted` 或纯 `Object`。
* **细分目录**：
  * `core/sim/`：战局确定性主仿真循环（`match_sim.gd`）、Tick 时钟调度、全局快照生成与回放。
  * `core/combat/`：战斗通用算法、物理碰撞判定（圆形/扇形/矩形相交）、伤害结算公式、护盾与增益状态（Buff/Debuff）计时器。
  * `core/skills/`：技能核心定义、施法前摇/后摇、施法消耗、冷却时间管理、弹道逻辑轨迹。
  * `core/entities/`：实体静态数值与动态状态定义（英雄属性表 `hero_defs.gd`、小兵/野怪属性、防御塔属性）。
  * `core/map/`：地图几何静态数据（`map_data.gd`）、防御塔与基地坐标、寻路航点（Waypoints）、泉水恢复边界定义。

### 2.2 `godot/scripts/view/`（3D 表现层）
* **定位**：消费 `core/` 派发的快照（Snapshot）与战斗事件（Events），负责 3D 视觉展示与动画平滑回放。
* **细分目录**：
  * `view/camera/`：战局相机跟随控制、平滑视距缩放（Zoom Glide）、震屏反馈。
  * `view/units/`：单位 3D 装配与动画分发。英雄部件拼接（身体/服装/发型/武器）、动画控制器（`AnimationPlayer` 调速与融合）、小兵表现。
  * `view/combat/`：普攻飞弹视觉表现、受击闪白、伤害飘字（基于对象池）。
  * `view/indicators/`：地面指示环组件（常驻金色普攻射程环、动态技能施法范围环、绿色呼吸移动落点标记）。
  * `view/environment/`：静态场景元素表现、防御塔激光光柱、基地泉水粒子光环、草丛晃动。
  * `view/effects/`：着色器材质运行时预热挂接、特效节点包装。

### 2.3 `godot/scripts/ui/`（2D 交互界面层）
* **定位**：负责 2D 界面排版、动效呈现以及玩家操作意图（Intent）的收集。
* **细分目录**：
  * `ui/common/`：全局主题定义（`game_theme.gd`）、通用样式板、字体配置常量。
  * `ui/hud/`：局内战斗主平视显示系统。
    * `ui/hud/joystick/`：移动虚拟摇杆（支持触摸跟随与相对相机方向转换）。
    * `ui/hud/skill_buttons/`：技能按键与轮盘瞄准（冷却遮罩、禁用态、拖拽瞄准向量捕获）。
    * `ui/hud/minimap/`：右上角小地图（防御塔图标、英雄雷达点、视野裁剪）。
    * `ui/hud/bars/`：单位头顶血条与蓝条（基于 `billboard_bar.gdshader`）。
  * `ui/screens/`：全屏主界面（主菜单、英雄选人室、战局结算面板、立体视差动态背景 `cinematic_background.gd`、立体卡片 `depth_card.gd`）。
  * `ui/popups/`：局内暂停菜单、断线重连对话框、退出提示窗。

### 2.4 `godot/scripts/net/`（网络与同步层）
* **定位**：处理客户端与服务端之间的数据包收发、输入上报与状态平滑。
* **细分目录**：
  * `net/client/`：客机网络会话管理、客机抗抖动缓冲（Jitter Buffer，平滑网络波动）。
  * `net/server/`：主机/独立服务器端会话管理、客户端输入收集与合并（Input Gather）、按固定频率向客机分发快照。
  * `net/protocol/`：网络协议定义（`net_protocol.gd`）、包序列化/反序列化、事件码枚举。
  * `net/discovery/`：局域网房间广播与自动探测（`lan_discovery.gd`）、心跳保活。

### 2.5 `godot/scripts/infra/`（基础设施层）
* **定位**：底层技术支撑，保障运行性能与平台通用抽象。
* **细分目录**：
  * `infra/pool/`：**全局对象池管理器**（打击粒子池、飘字池、弹道池）。真机杜绝运行时 `new`。
  * `infra/input/`：输入设备抽象适配层（`input_assist.gd`），将 PC 键盘/鼠标与移动端触摸统一转换为战局输入向量。
  * `infra/audio/`：音效播放器（BGM 循环播放、打击音效分发）。

### 2.6 `godot/scripts/app/`（应用生命周期层）
* **定位**：游戏顶级启动器与状态机。
* **核心内容**：
  * `app/main.gd`：游戏顶级节点，承载场景加载、全局错误捕获、窗口尺寸变动适配。
  * `app/bootstrap.gd`：启动时一键执行：着色器预热、对象池预热加载。

## 3. 开发五大架构铁律（强制执行）

所有代码审查、新增模块与重构必须严格对照以下五条红线：

### 铁律 1：Core 逻辑核纯洁性红线
* `core/` 下的代码**严禁出现任何关于 Node、Node3D、Control、Mesh、Material、Audio、Particles 的引用**。
* 严禁在 `core/` 中使用 `get_tree()`、`preload("*.tscn")` 或 `Engine.get_frames_per_second()`。
* **验收标准**：`core/` 的任何逻辑必须能够被单测脚本在 `--headless` 模式下以 1000 倍速脱离图形窗口纯数学运行。

### 铁律 2：View 表现层只读驱动红线
* `view/` 下的代码只有“读快照”的权力，**严禁在表现层直接改写血量、增减属性、触发胜负结算**。
* 当 View 检测到动画播放结束、子弹命中视觉抵达时，只能向 Core 派发视觉回调，具体数值判定完全以 Core 的 Snapshot 为准。

### 铁律 3：零即时分配原则（彻底根治真机卡顿）
* 战斗过程中，**严禁对高频短期对象调用 `.new()` 或 `queue_free()`**（包括但不限于：打击粒子、普通弹道、受击飘字 Label、技能范围光圈）。
* 战斗开始前必须通过 `infra/pool/` 进行预热分配；战斗中只能调用 `acquire()` 激活和 `release()` 回收。
* 小兵或实体的生成必须通过生成队列按帧平摊，严禁在同一帧瞬时 `instantiate()` 整波单位。

### 铁律 4：UI 单向意图流红线
* UI 控件（按键、摇杆、技能轮盘）只能产生 `UserIntent`（如“向方向 (1,0) 移动”、“释放 Q 技能到目标点”）。
* UI 严禁跨层直接操作 3D 角色（如：禁止在技能按钮的 `_pressed` 中直接让英雄播放施法动作）。所有意图统一提交给输入适配器，经由当前 Tick 模拟后再反馈至 View。

### 铁律 5：文件命名与单一职责规范
* 统一采用 `snake_case.gd` 命名文件。
* 类的职责必须单一，**单个文件有效代码行数原则上不超过 500 行**。如果一个文件超过 600 行，必须拆解为策略类或子组件。

## 4. 新增功能开发流程规范 (Development Flow)

当需要新增一个英雄、新技能或新机制时，严格按以下步骤推进：

```
Step 1: 编写单元测试 (tests/test_xxx.gd)
        定义预期数值与行为逻辑 -> 运行测试确认红灯（失败）
                     |
Step 2: 在 core/ 领域中实现逻辑
        编写 pure data & math 计算 -> 运行测试确认绿灯（通过）
                     |
Step 3: 做一次变异测试 (Mutation Check)
        刻意改错关键参数，确保单测必定抓到异常 -> 恢复正确代码
                     |
Step 4: 在 view/ & ui/ 挂接表现与交互
        绑定模型骨骼、指示器、HUD 按钮、特效对象池
                     |
Step 5: 真机性能验收
        运行 tools/perf_check.gd，确保 5v5 满负载帧率无毛刺
```

本规约为烽火峡谷项目的最高技术标准，后续所有新增文件与结构重构必须无条件对齐本基准。
