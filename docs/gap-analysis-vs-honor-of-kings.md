# 《烽火峡谷》对标《王者荣耀》差距分析（移动端为主视角）

> 生成日期：2026-11-09 ｜ 引擎：Godot 4.7.2 ｜ 目标平台：Android 优先
> 本文所有结论均落到 `文件:行号` 或一次可复现的实测，不以 `docs/upgrades/` 的"完成度表"为依据。
> 判断一个模块是否"真在跑"，按 `docs/ai/01-repo-reality.md` §4 的引用检查复现，而非"测试绿即完成"。

---

## 0. 一句话结论

《烽火峡谷》已经是一个**结构正确、工程纪律极好、单机手感闭环完整的 MOBA 玩法内核原型**；
但它和《王者荣耀》之间的差距，**不是"再多做几个功能"，而是三条主线的量级差**：

1. **它是一款"局域网同屏 10 人的对战 Demo"，不是一款"手游产品"**——缺账号、缺服务器、缺匹配、缺 progression（养成/皮肤/铭文）、缺一切联网基础设施；
2. **它的战斗深度是"单维数值"，王者是"多维属性公式"**——模拟层根本没有护甲/魔抗/攻速/冷却缩减/穿透/吸血这几条属性，伤害公式只有一个减法；
3. **英雄与表现的体量是"5 个换皮人偶"，王者是"上百个定制角色 + 全定制技能演出"**——资产、动画、特效、配音的工业量级不可同日而语。

而**"以手机端为主"这个目标本身，项目目前只完成了约 40%**：触控键位、摇杆、拖拽施法、取消区、48dp 命中区这些"能玩"的部分做得相当扎实；但**刘海/圆角安全区适配、帧率与画质分级、移动端发热与内存、公网弱网对抗、断线重连**这些"敢让真实玩家装在手机上"的部分基本是空白。

## 2. 架构与工程成熟度：这一层其实做得好

这是本项目最被低估的部分，先讲清楚，避免误判成"又一个玩具"。

- **Core-View 严格解耦是真的**：`sim/` 全部 `extends RefCounted`，零引擎节点、零渲染 API（`docs/ai/00-hard-rules.md` 第 2 条落地），确定性 30Hz tick，能在无头环境 100% 复现。这是 MOBA 权威逻辑的正确地基。
- **联机同步有真实工业味**：状态走不可靠有序、事件走可靠两条通道分离（`net/game_session.gd:378-386`）；快照按队伍过战争迷雾过滤防透视（`sim/map/vision.gd:138-169`）；整包 ZSTD 压缩；客机预测 + `last_input_seq` 对账 + 大误差瞬移/小误差衰减（`net/client_prediction.gd:92-107`）。
- **反作弊信任根扎实**：所有数值结算只在主机跑，`owner_id` 由 ENet peer 派生、不采信对端上报（`net/game_session.gd:289`），调试字段不进快照白名单。
- **表现层零 GC 抖动有纪律**：飘字/粒子/范围环/弹道全部走池、禁止战斗中 `.new()`/`queue_free()`（`docs/ai/00-hard-rules.md` 第 4 条 + `arena.gd` 的 6 个池）。
- **工程自检文档极成熟**：`docs/ai/` 11 份 + `routing.yaml`，尤其"文件在 + 测试绿 ≠ 功能在跑"这条，是全仓库最宝贵的经验，直接对应王者级别 QA 才会遇到的坑。

> 结论：**地基是对的**。下面的差距，绝大多数不是"架构错了"，而是"地基上还没盖楼"。

## 3. 玩法深度差距（模拟层，决定"像不像 MOBA"）

### 3.1 【最致命】战斗属性只有单维，伤害公式没有减伤

实测英雄实体的字段（`tools/pacing_report.gd` 直接读 sim hero 字典）：

- **存在**：`hp / max_hp / mp / attack_damage / attack_range / attack_interval / speed / crit_rate / ability_power / shield`
- **完全缺失**：`armor`（护甲）、`magic_resist`（魔抗）、`cooldown_reduction`（冷却缩减）、`attack_speed`（攻速加成）、`hp_regen / mana_regen`（回血回蓝只有常量脱战值 `FIELD_HP_REGEN=0.025 / FIELD_MP_REGEN=6.0`，`match_sim.gd:38-39`，不吃任何加成）、`penetration`（穿透）、`lifesteal`（吸血）、`crit_damage`（暴伤倍率，写死 1.5，`match_sim.gd:1012`）
- **攻速不可成长（已逐处 grep 证实）**：全工程没有任何一行代码修改英雄的 `attack_interval`——它只在 `wave_rules.gd:44/53/62`（小兵）与 `test_hero_survivability.gd:85` 被赋值。`item_shop.gd:142-168` 的 `recalculate_stats()` 只重写 `attack_damage / ability_power / max_hp / speed / crit_rate` 五项。**射手出装不会变快、攻速阈值与攻速收益曲线整个不存在。**

伤害结算主函数 `_damage()`（`match_sim.gd:1055-1144`）里，能改变 `incoming` 的只有三档全局系数：小兵/野怪对英雄打折 `0.62`、塔前期保护 `0.5`、红/首领 buff 增伤 `1.12`。**没有任何"目标防御属性参与计算"的项**——护甲是 0、魔抗是 0，物理伤害和法术伤害在数值管线里**走的是同一条路、同一个 `_damage`**。

**对标王者**：护甲/魔抗减伤、法术强度收益曲线、穿透、暴击伤害倍率、攻速上限与档位、冷却缩减上限（王者 40%）、每秒回复——这些是 MOBA 装备系统的**存在理由**。当前 `item_shop.gd` 只加 `ad/ap/hp/speed/crit` 五个数，所以**防御装的实际效果是把血上限抬高、而不是"更能扛物理/法术"**，出装的策略深度近乎为零。

**这是第一优先级**：它决定了"这个游戏是不是 MOBA"，而不只是"像个 MOBA 皮肤"。

> → 验收记录：**项 1 已实现（2026-11-09，[证据](acceptance-evidence/item01-20261109/README.md)）**。
> 护甲/魔抗/CDR/攻速/暴伤/回血回蓝 7 个属性已进 `_damage()` 与 6 处链路，
> `penetration` / `lifesteal` 两项**仍未做**。整体状态 🟨 进行中（差真机复验）。

### 3.2 技能没有等级、没有前摇后摇、没有弹道飞行

- ~~**技能不随等级成长**~~ → **已由项 2 修复（2026-11-09）**：`HeroDefs.scaled_damage()` 按 `damage + damage_grow*(技能等级-1)` 结算，Q/W/E 1..6 级、R 0..3 级，两条施法路径共用同一真身。
- ~~**大招无等级门槛**~~ → **已由项 2 修复**：`ULT_UNLOCK_LEVELS = [4, 7, 10]`，未学时施放失败且**不扣蓝、不进 CD**，HUD 播报解锁条件。
  > 代价（实测）：大招延后到 4 级 + 项 1 的装备减伤叠加，使 5v5 时长从 9m33s **回退到 15m00s 未分胜负**。
  > 这是门槛的真实代价而非 bug（王者同样 4 级才有大招），但**项 2 不能单独上线**，须与项 6（节奏标定）一起收口。
- **瞬发即时结算**：`_try_attack`（`match_sim.gd:1021`）和所有技能在施放的那个 tick 就直接 `_damage`，**没有弹道飞行时间、没有施法前摇/后摇**（grep `projectile/windup/cast_time` 在 `sim/` 全 0）。表现层画了个弹丸（`arena._spawn_projectile`），但逻辑早已结算完毕——**"走位躲非指向技能"在这个游戏里物理上不可能**，因为落点判定在按下瞬间就完成，玩家无法通过移动让技能 miss。这是与王者**操作上限层面最根本的差距**。

> → 验收记录：**项 2 已实现前两条（2026-11-09，[证据](acceptance-evidence/item02-20261109/README.md)）**。
> 第三条「瞬发即时结算 / 无弹道飞行」**仍未做**（属项 3），"走位躲非指向技能"目前依然不可能。

### 3.3 控制技能残缺

`sim` 里的状态只有 `slow_timer / haste_timer / shield / cc_immune_timer`。**没有眩晕、击飞、沉默、禁锢、定身、恐惧、嘲讽（`taunt_aura` 只是加盾+AOE，并不真正强制目标攻击自己）**。grep `stun/knockup/silence/suppress/frozen` 在逻辑层 0 命中。
王者一个刺客没有硬控链是不可想象的——当前"墨鸦"的爆发再高也无法"按住"目标。

### 3.4 召唤师技能形同虚设

`skill_system.gd:7-41` 定义了 4 个召唤师技能，但：
- 英雄出生**硬编码 `"summoner_spell": "flash"`**（`match_sim.gd:198`），
- 全工程**没有任何一处**调用 `get_available_summoner_spells()`（仅测试用到），
- 选人界面 / 大厅**没有召唤师技能选择 UI**。
结果：**玩家永远只能带闪现**。终结/净化/治疗写了逻辑却没有任何入口能装备它们——是典型的"文件在、逻辑在、玩家碰不到"。

### 3.5 兵线与野怪 AI 过于薄

- **小兵不寻路**：只沿固定航点折线 + 滑墙（`_advance_along_path`），**无 A* / 无 NavigationServer**（grep 0 命中）。墙一旦压住路面就永久堵车——`map_layout.gd:51` 的注释也承认这是硬约束。
- **野怪纯反击**：不主动索敌，只有被打才追（`_monster_target`，`match_sim.gd:480-496`，且这是 2026-10-24 用户定稿的有意设计）。这会让打野体验与王者差别很大（王者野怪有仇恨半径与巡逻）。
- **小兵之间无体积碰撞**：`Collision` 只做圆 vs 墙，**没有单位间分离**（grep `separation/repel/soft_body` 0 命中）。团战时小兵会完全重叠成一坨。
- **AI 无难度分级**：grep `difficulty` 0 命中，只有一套 `bot_ai` 布尔。没有"入门/普通/困难/职业"。

## 4. 移动端专项差距（这是用户目标的核心）

> 现状：触控"能用"做得好，触控"敢商用"做得差。逐项拆开看。

### 4.1 已经做对的（值得保留）

- **王者式键位布局成型**：右下普攻大键 152px + QWER 技能弧（半径 380、角度 186–264°）+ 底部功能横排（回城→传送→召唤师）+ 攻击键左侧普攻/补刀/推塔三模式圆（`scripts/ui/touch_layout.gd` 全文 + `docs/ai/05-ui-and-feel.md` §5.2）。这套几何**有真实血泪史**（330 半径时 Q 被回城键挡住点不到，见 `09-device-testing.md` §5）。
- **触控施法闭环完整**：按下出指示器 → 拖拽调向 → 松手施放 → 拖到顶部取消区中断（`skill_indicator.gd` / `cancel_cast_zone.gd`，已接线）。
- **48dp 命中区下限有测试兜底**：`TouchLayout.MIN_DP = 48.0`，`test_mobile_ui.gd:35-46` 按真实 480dpi 逐控件验 `dp_for_virtual`。
- **摇杆支持多点触控不抢占**：`touch_joystick.gd:74-88` 锁 `_touch_index`，左手摇杆 + 右手技能互不干扰（`docs/ai/09` MAN-03 人工验过）。
- **输入锁存不丢点**：20Hz 采样 + 点按类锁存（`_queued_*`），避免"点了没出手"。
- **真机自动化已跑通一轮**：`09-device-testing.md` §6 记录 2026-10-23 在 vivo V2220A 上 PASS=78/WARN=3/SKIP=13 的全流程，含硬解双视频、5v5 十英雄、GLES3 着色器编译。

### 4.2 严重缺口

**① 完全没有屏幕安全区 / 异形屏适配（移动端第一 blocker）**
grep `get_display_safe_area / safe_area / notch` 在**生产代码 0 命中**。`hud_layout.gd` 的分区全按 `MARGIN = 16` 硬算矩形，**没有读 Godot 的 `DisplayServer.get_display_safe_area()`**。刘海、挖孔、圆角、全面屏手势条会直接压在左上小地图、右下技能弧、底部回城条上。`docs/ai/09` 里 DISP-07 / SAFE-01/02 把圆角压控件标为"只允许 cosmetic WARN"——**意味着当前是已知会压、只是没升级为 FAIL**。换一台刘海机（`MAN-06` 明确列为"必须人工、未覆盖"）大概率翻车。

**② 没有画质分级/帧率目标/动态分辨率（移动端发热与续航的命门）**
- 无运行期画质开关：grep `quality / max_fps` 在 `scripts/` **0 命中**（`Engine.max_fps` 只在 `tools/` 截图脚本里设）。`project.godot` 只有一个**编译期**固定 `scaling_3d/scale.mobile=0.72`（`project.godot:35`）。
- 降级全靠 `OS.has_feature("mobile")` 的**单一 bool 分支**（`arena.gd:1899/2712/2921`：地表 shader 砍层、岩脊合批、草簇 12000→6000），**没有"低/中/高/超高"四档**，低端机和旗舰机拿到的是同一份配置。
- 王者对千元机到中端机有完整画质矩阵 + 动态降分辨率 + 帧率档位（30/60/90/120）。这里**一个滑块都没有**，也没有设置界面让玩家手动降。

**③ 没有设置界面（音量/画质/键位全都不能调）**
grep `settings / 音量 / 画质 / 键位重绑` 在生产代码 0 命中。
- 音乐/音效/语音**三条音量轨都不能调**（`audio_director.gd` 的音量和淡入淡出走的全是硬编码常量）；
- 键位**不能重映射**（`InputAssist` 里没有 InputMap 编辑入口）；
- 画质/帧率/分辨率/振动**全没有**；
- 甚至没有 `user://` 持久化——grep `ConfigFile / user://` 在生产代码 0 命中，**连"玩家的设置存哪"这套机制都不存在**。

**④ 联机=局域网，手机上几乎等于"没有联机"**
这是移动端最致命的结构性问题（网络子代理逐行核实）：
- **没有公网/服务器/中继/NAT 穿透**：只有 `ENetMultiplayerPeer` + `255.255.255.255` UDP 广播发现（`lan_discovery.gd:96-111`）。**两台不在同一 Wi-Fi 的手机，无法联机**。grep `NAT/STUN/TURN/relay/dedicated_server/公网` 0 命中，`export_presets.cfg:7` 显式 `dedicated_server=false`，无任何服务器入口代码。**公网对战从架构上就不可能**。
- **Listen Server 的移动端死穴**：房主既算 sim 又是玩家。房主手机一来电话/切后台/进锁屏（`MAN-07` 人工项），**全场 9 人一起掉线**——因为客机检测到主机断开直接回主菜单、无重连（`game_session.gd:240-245`）。移动端流量场景下这是常态事故。
- **RTT 显示是假的/缺失**：协议定义了 `ping/pong`，但客机处理分支**没有 `pong` case**，pong 被静默丢弃，全仓无 `rtt/latency` 变量——**连"延迟多少毫秒"都测不出来，HUD 上也就没有王者那个 460ms/延迟预警**。
- **无断线重连、无中途加入、无观战**（`06-net-sync.md` §8 自己承认）。唯一亮点是**掉线托管 AI** 做了（客机掉线→其英雄转 bot，`arena.gd:1334-1338`）。

**⑤ 团战事件包存在截断上限（实测：当前 AI 局未触发，但风险窗口真实存在）**
`net_protocol.gd:11` `MAX_EVENTS = 32`，超出直接丢弃（`:231/:266`）。本文档实测（`tools/pacing_report.gd`，5v5 全 bot、按 10Hz 广播口径统计两次广播之间累计事件）：**8980 个批次全部 ≤32，峰值 22**——即"团战必溢出"的说法**不成立，予以纠正**。但该上限对**真人 10 人局**仍是未验证的风险：人类技能密度（走 A 兵线 + 频繁补刀 + 更多位移技能事件）与击杀事件都高于 bot，且仓库没有任何针对真实团战事件量的测试。稳健结论：**这是"缺压力测试的已知约束"，不是"已确认的线上丢事件"**。修复方式是把事件改为增量/优先级下发，并用真人局数据定容量。

**⑥ 纹理压缩没为移动端全量开启（显存/包体/加载）**
`vram_compression/import_etc2_astc=true` 虽在 `project.godot:31` 开了，但**实际只有少数贴图导入成了 VRAM 压缩**：`assets/ui/` 下 14 张 PNG（含 5 张英雄立绘、`key_art.png` 1792×1024）**全是 RGBA8 未压缩**（`.import` 里 `vram_texture: false`、`compress/mode=0`）。实测尺寸：5 张立绘均为 **1024×1024**，未压缩即 **4.0 MB/张、合计 20.0 MB 显存**；`key_art` 1792×1024 另占 **7.0 MB**。转 ETC2/ASTC 后约省到 1/6（20 MB→约 3.3 MB）。对 2–3GB 内存的中低端机，这 27 MB 是显存常驻的相当比例，也直接推高 120.4 MB 的 APK。

### 4.3 移动端 UX 上缺失的"王者标配"

- **无小地图信号 ping（团队标点）**：`minimap.gd:4-8` 只有 `location_clicked / location_dragged / drag_finished` 三个信号，用途是**本地镜头聚焦 + 地图情报面板**（`sim/map_intel.gd`），**不是发给队友的标点**。全仓无 `chat` / 快捷语音 / 标记广播；`net_protocol.gd:27-42` 的 14 个消息类型里也没有任何一条用于玩家间通信。王者三指玩家的命脉（"敌人消失""请求支援""进攻"）完全没有。
- **快捷购买只有"一键买推荐"，没有出装方案**：`shop_panel.gd:77,261` 有"快捷购买推荐装备"（来自 `ItemShop.BUILD_ORDERS` 每英雄一条**写死的**顺序），但**无多套方案可切换、无合成路线展示、无"预购下一件"**。移动端纯靠手点在 8 件平铺里找装备，操作成本远高于王者。
- **无智能施法/辅助瞄准开关**：王者有"技能轮盘+头像锁定+高级瞄准"多档。这里 `AUTO_AIM_RANGE` 自动索敌是**写死开启、玩家不能关也不能调**。
- **无"伤害/血量数值/暴击飘字差异化"**：飘字只有 `amount>=150 金色 else 近白`（`05-ui-and-feel.md` §4），缺**受击闪白、护盾吸收字、低血量屏幕红晕**——文档 §4 明写"运行时仍然没有"。这些是移动端"打没打到"的关键即时反馈。
- **视频背景走 CPU 解码，菜单是常驻功耗项**：主菜单背景 + 5 条英雄展示视频共 31.9 MB `.ogv`，由 `VideoStreamPlayer`（Theora 软解）常驻播放。`device_checks.py` 的 VIDEO 系列只验"是否出帧上屏"，**没有验解码功耗**；`MAN-08`（低端机绿屏/黑屏）至今是"必须人工"项。低端机上"开着菜单就发热掉电"是真实风险，建议：低端档位直接回落静态立绘（`bgm_synth.gd:6` 与 `README` 都说明过回落链路存在，但触发条件是解码失败而非画质档位）。

### 5.1 合规与内容留痕（商用手机游戏的硬门槛）

- **3D 资产完全没有版权元数据**：抽样解析四族导出器的 glb（`Khronos glTF Blender I/O`＝hero_warrior/hair_*、`glTF-Transform`＝Orc/Skeleton_*、`FBX2glTF`＝environment 全系、`trimesh`＝weapons 全系），`copyright` 与 `license` **字段根本不存在**（不是"空字符串"，而是连声明位都没有），只剩导出器签名可追溯。仓库把 `godot/assets/**` 标为 `linguist-vendored`（`.gitattributes:24`），**但"vendored"不等于有授权记录**。字体（思源黑体 17.8MB + 马善政毛笔 5.9MB）同样**无任何许可证文件**；`README.md:43` 只写了两个字体名。
- **AI 生成链路的原始凭证只存在于本机、不入库**：`.video_gen/`（286.85 MB，被 `.gitignore:93` 忽略）里的 `.cache.json` 完整记录了百度 AIGC 接口（`bj.bcebos.com`、`AigcImageTask`/`AigcVideoTask`）的 prompt 与产物路径。**一旦换机或清理，立绘/视频的生成来源就无法举证**。
- **文案与实现已经出现自相矛盾**（内容治理缺口的直接证据）：翎羽被动写「提升移速**与攻速**」（`hero_defs.gd:89`），但实现只设 `haste_timer`、且 `haste_timer` 只作用于移速 ×1.4（`skill_system.gd:248` → `match_sim.gd:754-755`）；**全仓库 `attack_speed` 标识符 0 次出现**。玩家按描述出装预期落空。
- **仓库内文档数字已与实测漂移**：`README.md:66,168-170` 称 `.godot` 约 350MB、`shots` 约 365MB/近 300 张、APK 约 80–84MB；实测为 **295MB、143.7MB/175 文件、120.4MB**。按 `08-delivery-checklist.md` 第 5 项（文档与代码一致）这本身就是待修项。

## 7. 需要完善的清单（按"移动端为主"排的优先级）

### P0 · 先让它"配得上叫手游 MOBA"（战斗与属性地基）

1. **加战斗属性系统**：护甲/魔抗（引入减伤公式 `damage/(damage+k·resist)`）、法术强度收益、冷却缩减（含上限）、攻速加成与档位、暴击伤害倍率、每秒回血回蓝。**把 `_damage()` 从"一个减法"改成"按物理/法术/真实分型结算"**。这是所有其它玩法的前提。
2. **技能等级化**：给每个技能加"可随英雄等级点升"的成长；大招设 4/7/10 级解锁门槛——恢复 MOBA 的节奏曲线。
3. **弹道与前后摇**：非指向技能在 sim 里引入飞行时间与可被走位规避的判定（否则没有操作上限）。至少先做"施法前摇窗口内可被打断"。
4. **补硬控**：眩晕/击飞/沉默/定身 + `cc_immune` 统一消费，让刺客/坦克真正"控得住人"。
5. **召唤师技能可选**：在选人/大厅加技能选择 UI + 写进联机输入白名单与配置，把已有的 4 个技能真正开放给玩家。
6. **兵线节奏重调**：按 §1 实测，把 1v1"15 分钟推不平"和 5v5"2 分钟掉一塔"两头修中间——建议延长塔前期保护或提高水晶血量、并让兵线随时间加速，把单局压到 8–12 分钟。

### P1 · 再让它"敢让真实玩家装进手机"（移动端产品化）

7. **屏幕安全区适配**：`hud_layout.gd` 全面接 `DisplayServer.get_display_safe_area()`，把 `MARGIN=16` 换成"安全区 inset"，对刘海/圆角/手势条逐边避让；补 `test_hud_layout` 的异形屏用例。
8. **画质分级 + 设置界面 + 持久化**：低/中/高/超高四档（阴影距离、草簇数、shader 层数、`scaling_3d/scale`）+ 帧率档(30/60/90) + 音乐/音效/语音三轨音量 + 键位重映射；用 `ConfigFile` 存 `user://`。这是"能不能上手玩"的分水岭。
9. **弱网对抗三件套**：真正跑通 RTT/丢包测量并上 HUD 延迟显示；自适应 jitter buffer（按实测 RTT 调 `NET_RENDER_DELAY`）；**断线重连**（session token + 状态回放或托管过渡）。
10. **事件包容量做压力验证**：真人 10 人局实测事件峰值并据此定 `MAX_EVENTS`（现 32，bot 局峰值 22 未触顶但人类密度必然更高），顺手统一 `crit_rate` 的两处 clamp 口径（`net_protocol.gd:335` 限 5.0 vs `:411` 限 1.0，同一字段两条路径不一致）；并清掉两个死接口：`sanitize_hello()` 生产从未调用、客机不处理 `pong` 导致 RTT 永远测不出（先修 pong，P1-9 的延迟显示才有数据源）。
11. **移动端信号 ping + 快捷出装方案**：小地图标点（"敌人消失/请求支援/进攻"）与局外 3 套装备方案 + 局内一键预购——这是移动端 MOBA 的操作刚需。
12. **纹理压缩全量开启**：把 `assets/ui/` 14 张未压缩 PNG（尤其 5 张立绘 + `key_art`）改 ETC2/ASTC，压显存、压包体。

### P2 · 内容体量与联网架构（长期，需要"换赛道级"投入）

13. **公网服务器 + 匹配 + 账号**：从 Listen Server 迁到 **dedicated server**（Godot 有 `dedicated_server` 导出与无头 server 模式），补 NAT 穿透/中继、账号鉴权、MMR 匹配、赛季段位。这是一整条后端工程线。
14. **英雄扩到 15–20 个 + 每个定制模型与技能演出**；补装备合成树（先做到 40–60 件）。
15. **合规与本地化**：接多语言（现在全硬编码中文，补 `tr()` + CSV）；补资产授权声明；上 CI（headless 测试 + 自动导出 APK + `device_checks.py`）。
16. **拆分巨石文件**：`arena.gd`(**4298**) 按 `docs/ARCHITECTURE.md` 的目标态拆 `view/camera|units|effects|indicators`；`main.gd`(**1460**) 拆 `screens/`。这是**还技术债**，越晚越贵。

## 8. 给决策者的一句话

如果目标是"对标王者的手机 MOBA 产品"：**当前完成的是最难、也最有价值的 20%——玩法内核与架构地基**；剩下 80% 是"战斗属性公式（P0）+ 移动端产品化（P1）+ 联网内容与运营（P2）"。**建议先集中火力打穿 P0 的属性系统与 P1 的安全区/画质分级/设置/弱网**，因为这四件事决定"它玩起来像不像 MOBA、敢不敢发给真人装在手机上"；P2 的公网服务器与英雄量产是另一场战役，需要先做架构决策（Listen Server → Dedicated Server）。
