# AI 工作区 · 必读索引

> 给所有在本仓库工作的 AI 模型（换会话、换模型、换工具都一样）。
> 目的只有一句：**动手前知道这个项目"哪里不能碰、改一处要连带改几处"**，避免产出"看着对、跑起来静默失效"的代码。

---

## 阅读规则

1. **每次会话开始，必读三份**：本文件 → `00-hard-rules.md` → `01-repo-reality.md`。合计约 5 分钟。
2. **动手前按下面的表查任务**，只读对应文件，不必通读全部。
3. 同一份路由有机器可读版本 `routing.yaml`（字段 `task` / `read` / `touch` / `verify`），供自动编排直接解析。
4. 本目录与 `docs/ARCHITECTURE.md` 冲突时，**以本目录为准**，并在同一次提交里修正 ARCHITECTURE.md（见 `08-delivery-checklist.md`）。

---

## 先记住这三件事

1. **`scripts/core/` 和 `scripts/infra/` 是空壳**，只有 README。往那里写代码 = 写死代码。真正的逻辑在 `godot/sim/`。
2. **本仓库曾出现 8 个模块"文件在、测试绿、生产代码引用为 0"**（锁敌、指示器、取消施法、顿帧、播报、客户端预测、金币、装备），2026-10-23 已全部接线。新模块仍必须先跑 `grep` 确认生产引用。
3. **联机有白名单**，不加进 `net/net_protocol.gd` 的字段只在单机生效，而且不报错。

这三条都是**静默失效**——不报错、测试也绿，只是游戏里没效果。细节分别在 `01-repo-reality.md` §4、`00-hard-rules.md` 第 9 条、`06-net-sync.md` §4。

## 为什么分这么多文件

一个模型不可能每次都读 5 万字。按**任务类型**切分，让"改 UI 的模型"不用读联机协议，"写测试的模型"不用读 Godot 环境坑——**读得少，才读得进去**。

`.md` 是给模型读的自然语言细节，`.yaml` 是给编排层读的结构化路由，两者内容一致、用途不同。

## 维护约定（重要）

- 你**改动了本目录描述的行为**（例如把 `_local_input` 补齐成 4 个技能、给协议加了白名单字段），**必须在同一次提交里更新对应文件**。否则下一个模型会照着过期规则干活，而且它不会怀疑这份文档。
- 本目录只写**现状 + 约束**，不写愿望。想做的功能写进 `docs/upgrades/`。
- 新增一类任务（比如"做新手引导"），在这里加一行路由 + 一个文件，不要往已有文件里硬塞。
