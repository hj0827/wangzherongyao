## 0. 本项做了什么（按"先测量、后调整"的顺序）

1. **修测量工具**：旧 `pacing_report` 用 900 秒硬上限，会把"还没打完"打印成
   "15m00s 未分胜负"——两者结论完全不同。改为 1800 秒上限，并支持
   `--samples / --limit / --mode / --comps` 做多样本抽样（项 6.1 要求）。
2. **给 sim 加 `seed` 与 `bot_comp`**：没有这两个开关，"多 seed × 多阵容"只是
   同一局跑 N 次，中位数毫无意义。默认值保持原样，故既有对局逐位不变。
3. **查根因**（不调参、先定位）：用 5 组探针逐步排除，最终找到 **2 个真 bug**。
4. **修 bug + 补回归测试 + 变异验证**。

## 1. 查到的两个真 bug（都不是"数值不平衡"）

### Bug A：基地/双子塔解锁写成了 ALL，应为 ANY

`tower_rules.is_base_vulnerable` 与 `crystal.is_guard_vulnerable` 都要求
**三路高地塔全部倒下**才解锁，而：

- `tower_rules.gd:3` 注释写"**任意一路**高地塔倒下，基地才会暴露"
- `crystal.gd:4` 注释写"任意一路高地塔倒下后双子塔解锁"
- 测试名 `test_base_is_locked_until_a_high_tower_falls`
- 王者峡谷的实际规则

四处都说 ANY，只有代码是 ALL。

**为什么既有测试没抓到**：所有相关用例都只造一路塔（`_sim()` 默认 `mode="duel"`，
1 路只有 1 座 high）。在单路下 ANY 与 ALL **恰好等价**，所以写错也一直绿。

**实测后果**（`probe_pacing_stall`）：5v5 在 8m11s 就 `base_exposed`，
但 14 分钟里塔血纹丝不动（wave 40→70 塔数恒为 4），对局拖到 23m11s。
原因是剩下某个高地在守方手里时，基地与双子塔**永久免疫**——玩家看到的是
"推到高地就再也打不动了"。

### Bug B：边路塔位蓝红不对称，恒定偏 0.295m

`tower_anchor()` 原先让双方各自"沿路径量弧长"取点，但边路两侧路径的采样点
并不点对称，于是同一 progress 落在不同位置：

| 路 | 蓝塔离蓝基地 | 红塔离红基地 | 差 |
| --- | --- | --- | --- |
| mid | 46.839 | 46.839 | **0.000** |
| top outer | 67.812 | 67.518 | **0.295** |
| top inner | 45.091 | 44.797 | 0.294 |
| top high | 33.760 | 33.467 | 0.293 |

偏差虽小，**方向恒定**，等于给一侧稳定的对线优势；中路恰好为 0，所以只看中路
永远发现不了。

修法：红方塔锚点由蓝方**对侧路**锚点做点对称 `(x,y)→(-x,-y)` 得出，
不再各自量弧长。修后六条边路塔差值全部 **0.000**。

## 5. 实测：修 Bug A 的效果（决定性）

`pacing_report --samples=2 --comps=2 --limit=1200 --mode=team`（4 样本）：

| 指标 | 修前 | 修后 |
| --- | --- | --- |
| 分出胜负 | 3/4（75%） | **4/4（100%）** |
| 落在 8–12 分钟带 | 1/3（33%） | **4/4（100%）** |
| 时长中位数 | 13m08s | **11m01s** |
| 时长 p90 | 18m23s | **11m14s** |

这正是验收表 6.2（8–12 分钟占比 ≥80%）与 6.3（首塔 3–5 分钟）想要的方向。
首塔仍偏早（median 2m27s），但它是**稳定值**而不是僵局征兆。

## 6. ⚠️ 未解决：镜像对局存在稳定的红方优势（必须报告）

修完两个 bug 后，我做了镜像公平性检验：**同一套阵容同时给两队、只换 seed**。

| 阶段 | 结果 |
| --- | --- |
| 修 Bug A 前 | 红方 **10/10** 胜 |
| 修 Bug B（对称性）后 | 红方 **9/10** 胜 |

**结论：对称性修复没有解决胜率偏向。** 这是独立于地图几何的第三个问题。

已排查并**排除**的方向：

- 出生点：蓝红精确点对称（最大偏差 **0.000m**）
- 塔位：修后两侧离自家基地距离全部相等（0.000）
- 分路分配：双方同为 `LANE_ORDER[slot % 3]`，拿到相同路
- 路径配对：`blue top` 的镜像与 `red bottom` 最大最近距离 4.00m（配对正确）

**已观测到的现象**（`probe_bias_detail`，同阵容一局）：
蓝方 blade `cs=40 / 金币4360`，红方同位置 blade `cs=15 / 金币821`；
蓝方剩 1 塔、红方剩 6 塔，**蓝方推塔占优却输掉比赛**。
即两侧同职业的发育与推进效率差异很大，指向 bot 寻路/索敌与路径方向的相关性，
而不是资源或建筑规则。

**为什么不在本项继续修**：
1. 这是**行为 AI** 层面的问题，改动面比前两个 bug 大得多（`_update_bots` /
   `_nearest_enemy` / `_advance_along_path`），需要独立的探针与回归集；
2. 前两个 bug 已让节奏进入 8–12 分钟带并 100% 分胜负，项 6 的**标定目标**基本达成；
3. 用未定位清楚的改动去"凑胜率"会引入更难查的问题。

**建议**：单独立项（暂记 **项 6b「对局公平性」**），先做 bot 行为的双盲镜像回归，
再动 AI。
