## 1. 已修复的 3 个真实 bug

### Bug 1：单位卡死在野区围墙里（已验证修复）

**症状**：同阵容镜像局稳定 9/10 ~ 10/10 由红方获胜，但**没有任何报错、单局也能打完**。

**根因**：实体沿 waypoint 前进，`Collision.move` 会把"被墙挡住"的位移吃掉大半
（实测一次只走 0.0378m 而非 0.26m，即被吃掉 85.5%）。
而"到点"判定要求距离 < 0.9m —— 于是实体钻进野区围墙后**永远到不了点**，
`path_index` 也永不前进。

**实测后果**：蓝方射手卡在 `(0.38, -29.59)` 整整 6 分钟，CS 停在 4；
同阵容红方同位置 CS 是 32。**人数优势让红方稳定获胜**。

**修复**：
- `_advance_along_path` 增加"waypoint 距离 > 12m 则按最近点重吸附"；
- 增加撞墙检测：实际位移 < 应走距离的 50% 连续 30 帧即重吸附。

**验证**：修复后小兵从卡死变为 4.4m/s 正常推进，`stuck_ticks` 峰值 = 0。

### Bug 2：重吸附把实体吸回出生点，造成新的死循环（已验证修复）

第一版 `_resync_path_index` 会无条件"往前多取一格"，结果：
小兵刚离开出生点 → 被吸回 `idx=0`（出生点本身）→ "已到点"立刻成立 →
索引 +1 回到 `idx=1` → 下一帧又被吸回 `idx=0`……

**症状**：每 30 帧只有第 0 帧动 0.1m、其余原地不动，位移恒为 0。
`test_match.gd::test_minions_spawn_and_advance` 因此变红。

**修复**：吸附只能**沿前进方向推进，绝不回退**
（`dir > 0` 取 `max(best, current)`，反之取 `min`）。

### Bug 3：边路小兵起步点两侧不等距（已验证修复）

边路是**螺旋线**（先绕地图远端再回来），`path[1]` 与 `path[size-2]` 到各自基地的
**实际弧长并不相等**：

| 位置 | 到自家基地弧长 |
| --- | --- |
| top 路 `idx=1` | 12.65m |
| top 路 `idx=13` | **8.94m** |

红方小兵因此少走 3.7m，每波都先接触。实测**红方第 8 秒就出手、蓝方第 11 秒才有动作**。

**修复**：改为按**弧长**（`MINION_SPAWN_OFFSET = 12.0`）从自家基地端点取索引，
两侧严格等距。修复后双方小兵离自家基地都是 2.6~2.8m。

## 2. ⚠️ 核心问题未解决：镜像局仍 10/10 红方胜

三个 bug 修完后（`stuck_ticks` 峰值 0、双方起步等距、1014 测试全绿），
**镜像对局仍然是 10/10 红方获胜**。

### 已用数据排除的可能原因

| 假设 | 检验方法 | 结论 |
| --- | --- | --- |
| 出生点不对称 | 逐英雄点对称配对 | **排除**：偏差全部 0.00m |
| 塔血量不等 | 双方塔总血量 | **排除**：都是 28800 |
| 路径弧长不等 | 正序/逆序累计弧长 | **排除**：189.8427 = 189.8427 |
| 初始朝向不对称 | `facing_red == -facing_blue`？ | **排除**：全部满足 |
| 遍历顺序导致后手优势 | 反转 / 交错实体顺序 | **排除**：三种顺序都是红方胜 |
| 确定性系统有隐藏随机 | 同 seed 重复 3 次 | **确认确定性**：3 次都是 374s 红方胜 |
| 地图几何/分路分配 | 逐英雄到敌基地距离 | **排除**：蓝红逐位相同 |

### 仍未解释的观测

- 前 30 秒红方主动出手 **63 次**、蓝方 **47 次**（多 34%）；
- 但双方**承受伤害几乎相同**（8964 vs 8858）；
- 同阵容镜像局，红方 CS 稳定更高（约 +30%）。

### 我的判断

规则层面已用数据证明**完全对称**，所以偏向来自 **bot 行为代码中的某种不对称**，
但不在"坐标/朝向/顺序"这类显性维度上。可能方向（尚未验证）：

1. `_nearest_enemy` 的 `hero_dist` 扣 0.65、塔扣 `radius*0.7` ——
   这些偏移在不同几何位置下可能放大成不对称；
2. 技能射程判定（`ring`/`cone`）在 `(x,y)` 与 `(-x,-y)` 下是否严格镜像；
3. 野区营地的镜像是否真的一一对应（`test_jungle_walls` 只校验"有孪生"，
   不校验"位置对称"）。

**我没有继续盲改。** 上面三条都需要独立的探针与回归，强行调参只会产生
"看起来变好、换个 seed 又变"的假象 —— 这一点在项 6 的塔血量扫描里已经吃过大亏
（见 [6b 修复一轮 §2.1](../item6b-fix1-20261110/README.md)：塔血 ×1.4 反而让对局更短）。

## 4. 下一步建议

6b 若要继续，应该按**"先定位、后修改"**的顺序，且每次只验证一个假设：

1. **写一个"完全对称性检验"探针**：把 sim 的所有实体状态（位置/朝向/属性）
   在 `(x,y)` 与 `(-x,-y)` 下逐一比对，找出第一帧开始出现差异的地方。
   这比逐个假设试错快得多，也能直接指出是哪个模块破坏了对称。
2. 若确认对称性无损，则问题在**行为决策**（如"朝最近的敌人走"在两侧的
   选择序列不同），需要给 bot 加**决策日志**逐帧比对。

在拿到"镜像局红蓝各 50%"之前，**不应信任任何节奏标定数字** ——
因为一半的局被系统性偏袒了。
