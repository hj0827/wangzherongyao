## 0. 一句话结论

**2D 第一眼接近王者，3D 一进对局就露馅。**

本项目的美术是三种语言拼起来的：

1. **AI 写实国风立绘 / 视频 / 物品图标**（选人界面、商店）；
2. **程序化低模**（野怪、防御塔、地形、城墙、草丛）；
3. **第三方通用低模角色包**（英雄身体、小兵、狼、岩石）。

三者单看都不差，但放在同一帧里**不是同一个世界**。和王者荣耀的差距，主要不是"某个特效不够亮"，而是：

- **英雄**：5 个英雄只有 2 套身体模型，靠换发型、换衣服、换武器、染色拼出来；立绘里的角色和对局里的模型不是同一个人。
- **野怪 / 小兵**：基本体拼装、无贴图、无攻击/受击动作；小兵四种类型共用同一套模型。
- **场景 / 城墙**：可玩区严格平地、贴图四套复用、墙体是"砖基座 + 162 面岩石块"重复铺；王者峡谷的悬崖、台地、植被层次基本没有。
- **UI**：布局和可读性是强项，但技能图标是 5 族矢量符号（17 个技能共用），不是王者那种"一个技能一张画"。
- **特效**：环、球、方片三种基本体 + 纯色材质；没有贴图、没有序列帧、没有地面残留、没有受击闪白。框架（池、顿帧、震屏）很专业，但**视觉资产为零**。

如果以"能上线的手游视觉"为 100%，当前大约在 **30–40%**（主观估算，不是度量）。其中 UI 布局约 60–70%，3D 角色/野怪/场景约 20–30%，技能特效资产约 15–25%。

## 1. 总览评分

差距等级：**S** = 要重做整条生产线；**A** = 需要专项美术投入（1–3 个月）；**B** = 1–2 周打磨可显著缩小；**C** = 已接近，只差细节。

| 类别 | UI / 信息呈现 | 外在形象（剪影/风格） | 模型 / 材质 | 特效 / 动态 | 综合 |
| --- | --- | --- | --- | --- | --- |
| 物品（装备） | B（商店太素） | B（图标质量尚可） | —（无 3D 物品） | B（无被动视觉） | **B+** |
| 英雄 | B（选人强、局内弱） | **S**（2 套身体） | **S**（通用低模） | A（技能动画共用） | **S** |
| 野怪 | B（营地 UI 完整） | A（基本体拼装） | A（无贴图） | A（无攻击/受击动作） | **A** |
| 场景 | B（小地图/分区清楚） | A（平地 + 贴图复用） | A（四套贴图） | B（水面/草有动效） | **A** |
| 城墙 | C（碰撞与视觉同源） | A（矮、重复、灰） | A（单块 Rock 重复） | C（静态） | **A** |
| 局内 HUD | B | B | — | B | **B** |
| 技能特效 | — | A（形状语言单一） | A（无贴图资产） | A（无残留/闪白） | **A** |

**最刺眼的三个断点**（按"玩家第一眼会出戏"排序）：

1. **选人立绘 vs 对局模型**：苍刃立绘是黑甲大剑的国风剑客，对局里是绿色游侠皮甲 + 一把比例夸张的 Claymore；星璃立绘是紫发星月法袍，对局里是紫染长袍 + 镰刀。玩家会觉得"点进去换了个游戏"。
2. **野怪/小兵是"基本体"**：蓝 BUFF 是几块方石叠起来，红鸟是球 + 三角翅膀，小兵四种类型同一副骷髅。王者里每只野怪都有手绘贴图、攻击动作、受击反馈、死亡消散。
3. **技能图标与特效没有"技能签名"**：17 个技能只有 5 族图标；同族技能图标完全相同，特效也是同一套环 + 火星，只是换颜色。

## 2. 物品（装备）

### 2.1 现状（证据）

| 项 | 现状 |
| --- | --- |
| 数量 | **8 件**：4 件基础（铁剑 / 咒术典籍 / 布甲 / 神速之靴）+ 4 件成装（无尽战刃 / 回响之杖 / 不祥征兆 / 抵抗之靴） |
| 合成 | **无合成树**，`CATALOGUE` 没有 `recipe / components` 字段（`sim/item_shop.gd:3`） |
| 图标 | 8 张 **256×256** 静物图，暗底、独立打光（`assets/ui/items/*.png`） |
| 商店 UI | 2 列平铺网格，无分类页签、无详情卡、无合成路径；描述是一行属性文本（`scripts/ui/shop_panel.gd:88`） |
| 品质 | 无白/绿/蓝/紫/橙品质框，无边框差异 |
| 局内表现 | 装备只改数值；英雄身上没有装备外观、没有被动触发特效 |
| 空槽 | 背包空位显示"空"字（`shop_panel.gd:117`） |

### 2.2 王者基准

- **100+ 件装备 + 多级合成树**：小件 → 中件 → 成装，商店里能直接看到"下一件"和合成路径。
- 每件装备有**独立手绘图标**：统一 3/4 视角、统一描边、统一背景色系，并按品质加边框。
- 商店有**分类页签**（攻击 / 法术 / 防御 / 移动 / 打野 / 辅助）、推荐出装、预购、装备详情（被动描述 + 数值 + 合成件）。
- 装备被动有**可感知的视觉**：暴击、回血、护盾、减速、灼烧，都会在角色或目标身上留下反馈。

### 2.3 差距拆解

| 层 | 差距 | 影响 |
| --- | --- | --- |
| UI | 商店是一张"表格"，不是"装备界面"：没有分类、没有详情、没有合成树、没有品质框 | 玩家找不到装备，也看不懂"为什么买它" |
| 外在形象 | 图标是孤立静物，暗底、无统一描边/视角；和金色 UI 面板不是一套语言 | 8 张图单看不错，放进商店像从不同游戏抠来的 |
| 模型 | 无 3D 物品、无掉落物、无装备外观 | 不是必须，但少了"装备感" |
| 特效 | 无尽战刃的暴击只是刀光变白；不祥征兆的减速/回血没有任何视觉 | 装备被动"看不见"，玩家只能读数字 |

### 2.4 补法

- **P0（1 周）**：给 8 件装备加品质框 + 分类页签 + 详情卡（属性、被动、价格、合成件）；商店从"2 列列表"改成"左侧分类 + 中间网格 + 右侧详情"。
- **P1（2–3 周）**：补到 16–20 件，建立 1–2 层合成树；图标统一重打光（同一 3/4 视角、同一描边、同一暖背景）。
- **P1**：把已有被动接上视觉钩子——暴击闪白、回血绿色上浮、护盾泡、减速脚下冰环。

## 3. 英雄

### 3.1 现状（证据）

| 项 | 现状 |
| --- | --- |
| 数量 | **5 个**：苍刃（战士）/ 星璃（法师）/ 铁壁（坦克）/ 翎羽（射手）/ 墨鸦（刺客） |
| 身体模板 | **2 套**：`hero_warrior.glb`（苍刃、铁壁）、`hero_mage.glb`（星璃、翎羽、墨鸦） |
| 拼装件 | 4 套衣服（ranger_m/f、peasant_m/f）+ 4 套发型 + 5 把武器，靠 `outfit_tint` 染色（`unit_visual.gd:72-138`） |
| 模型精度 | 身体约 **14–15k 三角面**，3 张 **1024²** 贴图（glb 内嵌） |
| 动画 | 从 UAL1/UAL2 两套通用动作库 retarget；每个英雄只映射 1 个普攻 + Q/W/E/R 各 1 个通用 clip（`unit_visual.gd:154-191`） |
| 专属动画 | **0**：没有技能专属动作、没有回城/出生/挑衅/待机变体、没有面部/布料/头发骨骼 |
| 皮肤 | **0** |
| 立绘 | 5 张 **1024²** 写实国风 PNG（`assets/ui/portraits/*.png`），选人界面 + 小地图头像 + 左下角头像都在用 |
| 展示视频 | 5 段 OGV（3.2–4.9 MB），选人界面播放（`scripts/app/main.gd:436`） |
| 队伍区分 | 蓝方整体染蓝 5%、红方染红 24%（`unit_visual.gd:391`） |
| 镜头 | 默认 zoom 21，英雄约占屏幕高度 **7%**（`unit_visual.gd:35-40` 注释实测） |
| 技能颜色 | 每个英雄一个谱系色（`arena.gd:4632`），形状按 `kind` 复用配方（`skill_fx.gd`） |

### 3.2 王者基准

- **每个英雄一张脸、一副骨架、一套动作**：剪影一眼可辨；服装、发型、武器、配色全部为角色定制。
- **立绘 / 模型 / 皮肤 / 特效 / 语音是同一个角色**：选人界面有 3D 展示、待机动作、技能预览、皮肤切换。
- 技能有**专属动作与专属特效**：同一个"斩击"在不同英雄身上，动作、刀光颜色、残留、音效都不同。
- 有布料/头发物理、面部表情、回城/出生/死亡/挑衅动作。
- 镜头更近：英雄约占屏幕高度 1/6（本仓库注释里已量过），细节看得见。

### 3.3 差距拆解

| 层 | 差距 | 具体表现 |
| --- | --- | --- |
| UI | 选人界面只有 2D 卡片 + 视频，没有 3D 预览、没有皮肤页、没有技能演示 | 选人界面看起来像成品，进对局像另一个项目 |
| 外在形象 | **2 套身体 + 4 套衣服 + 染色**，剪影没有辨识度 | 苍刃和铁壁共用战士身体；星璃/翎羽/墨鸦共用法师身体；体型差只靠缩放 |
| 外在形象 | 立绘是国风写实，模型是西式 low-poly 游侠/农民 | 苍刃立绘是黑甲大剑，模型是绿染游侠 + 巨剑；星璃立绘是星月法袍，模型是紫染长袍 + 镰刀 |
| 模型 | 通用包模型 + 1024 贴图 + 无面部/布料骨骼 | 拉到近景能看到低模接缝、布料穿插、手部僵硬 |
| 动画 | 通用动作库 retarget；Q/W/E/R 只是 4 个 clip 的映射 | 星璃和翎羽的 Q 都可能播 `Spell_Simple_Shoot`；大招和普通施法动作区分弱 |
| 特效 | 只有谱系色不同，形状按技能族复用 | 苍刃 Q（slash）和铁壁 Q（quake）都是"strike"族；星璃 Q（burst）和翎羽 W（aoe_shot）都是"burst"族 |
| 镜头 | zoom 21 下英雄仅占屏高 7% | 1024 贴图、面部、服装细节在实机上几乎看不见；继续加模型精度收益很低 |

### 3.4 结论

**英雄是视觉差距最大的一类，且不是"打磨"能解决的，是"资产生产线"问题。**

在现有镜头距离下，优先做**剪影与配色**（低成本、高收益）比做高模更划算：

- 先把 5 个英雄的**体型、肩宽、武器比例、主色**拉开；
- 让模型主色/武器/发型**对齐立绘**（至少让人认得出是同一个角色）；
- 再考虑定制模型、专属动作、皮肤。

## 4. 野怪

### 4.1 现状（证据）

| 项 | 现状 |
| --- | --- |
| 营地 | **12 个**：4 个 BUFF（蓝/红石像 ×2 边）、8 个小野点（双狼 / 蜥蜴 / 三猪 / 红鸟 ×2 边） |
| 中立 | 2 个首领（暴君 / 主宰）+ 2 个河道之灵 |
| 形态 | 7 种程序化形态（blue/red_sentinel、lizard、boar、bird、tyrant、overlord）+ 狼模型 + 水球 |
| 建模方式 | `monster_kit.gd` 用 Box/Sphere/Cylinder/Shard 拼；材质是纯色 `StandardMaterial3D` + emission，**无贴图** |
| 动画 | `monster_forms.gd:113` 只驱动：身体上下、腿摆、翅膀扇、尾巴摇、轨道旋转、核心缩放；**没有攻击 / 受击 / 死亡骨骼动作**（狼除外，Wolf.glb 有 8 个动作） |
| 死亡 | 程序化形态统一"向前倒 + 缩小 + 下沉"（`unit_visual.gd:1063`） |
| 首领 | 暴君/主宰共用一套 `_beast` 骨架，靠配色、角数、甲刺长度、背晶区分（`monster_forms_boss.gd:23`） |
| 小兵 | 蓝方 `Skeleton_Warrior.glb`、红方 `Skeleton_Rogue.glb`；四种类型（近战/远程/炮车/超级兵）**共用同一模型**（`unit_visual.gd:422`） |
| 营地 UI | 贴地圆盘 + 双环 + 旋转符阵 + 图腾柱 + 名牌 + 复活倒计时（`arena.gd:2509` 起） |
| BUFF 表现 | 野怪脚下有符阵；英雄拿走 BUFF 只有一圈扩散环（`arena.gd:3916`），身上没有持续 aura |

### 4.2 王者基准

- 每只野怪有**手绘贴图 + 专属剪影 + 攻击/受击/死亡动作**；BUFF 怪是"石像/魔像"，小野点是"兽"，首领是"巨兽"。
- 首领有**出场演出**（镜头、咆哮、地面震动）、技能预警、阶段变化、死亡演出。
- BUFF 有**持续视觉**：怪物身上的光环、英雄身上的红/蓝 aura、脚下印记。
- 营地有**环境叙事**：兽骨、巢穴、水晶、残破石柱，而不是所有营地共用一个圆盘 + 图腾。
- 小兵四种类型剪影差异明显（远程举杖、炮车有器械、超级兵更大）。

### 4.3 差距拆解

| 层 | 差距 | 具体表现 |
| --- | --- | --- |
| UI | 营地 UI 功能完整，但所有营地共用"圆盘 + 双环 + 图腾" | 12 个野点看起来像 12 个同款法阵；王者是环境本身在提示"这里有野" |
| 外在形象 | 基本体拼装，剪影能认但"纸壳感"强 | 蓝 BUFF 是方石叠罗汉，红鸟是球 + 三角翅膀，蜥蜴是几条方盒；没有毛发/鳞片/甲片细节 |
| 模型 | 无贴图、无法线、无 AO；纯色 + emission | 近看是塑料/纸模；远看靠颜色区分，细节为零 |
| 动画 | 只有待机/移动；攻击时**站着不动**，受击**没有反应** | 打野时怪物不还手、不缩身、不闪白，战斗反馈全靠飘字 |
| 首领 | 共用骨架；无出场演出、无技能预警、无死亡演出 | 暴君/主宰只是"更大的野怪"，没有史诗感 |
| 小兵 | 四种类型同一模型 | 兵线看起来永远是一排骷髅；没有炮车/远程的剪影差异 |
| BUFF | 拿走 BUFF 只有一圈环；英雄身上无持续 aura | 玩家不知道自己身上有没有红/蓝 BUFF，只能看 HUD 小图标 |

### 4.4 补法

- **P0（3–5 天）**：给程序化野怪加"攻击前倾 + 受击缩身 + 闪白"三个程序化动作；死亡加"溶解/下沉"；BUFF 怪加持续光环，英雄加红/蓝 aura。
- **P0（2–3 天）**：小兵按类型加配件——远程兵加弓/杖，炮车加器械，超级兵放大 + 换色；至少让兵线剪影不再单一。
- **P1（2–3 周）**：首领出场演出（镜头拉近 + 咆哮 + 地面冲击环）、技能预警圈、死亡慢动作；暴君/主宰换两套不同骨架。
- **P1（3–4 周）**：给野怪做一套共享的"手绘感"材质（顶点色 + 噪声 + 边缘光），比逐只做贴图便宜，能显著去掉塑料感。
- **P2**：逐只定制模型 + 贴图 + 专属动作。

## 5. 场景

### 5.1 现状（证据）

| 项 | 现状 |
| --- | --- |
| 地形 | 260m × 260m，128×128 网格，约 **5.1 万三角面**；可玩区（±58）**严格平地**，抬升只出现在墙外（`terrain_builder.gd:14`） |
| 地表 | 2 层草贴图 + 1 层泥土 + 坡度混岩石；阵营色偏 ±6%；墙外渐隐（`terrain_builder.gd:102`） |
| 贴图 | 全场景只有 **4 套**：`leafy_grass`、`grass_path_2`、`cliff_side`，各含 Diffuse/Normal/Rough/AO |
| 草 | **12000 簇**（移动端 6000），4 片叶/簇，随风摆动（`grass_field.gd`） |
| 草丛 | **10 丛**，每丛约 **1800 片叶**，2 套网格 + 1 套材质（`bush_field.gd`） |
| 树 | **可玩区内 0 棵**（刻意移除，避免挡兵线）；墙外只有 12 座低模山 + 16 块岩石 |
| 河 | 平面 + 自定义 shader：深浅色、两层波纹、岸边泡沫、墙外渐隐（`arena.gd:2105`） |
| 桥 | 中路一座石桥；边路角落改为铺装广场，无桥（`arena.gd:2276`） |
| 建筑 | 防御塔程序化（`tower_visual.gd`）；基地水晶 = 圆柱台 + 球体宝石 + 环 + 光柱（`arena.gd:3564`） |
| 环境建筑 | `Barracks / Market / Temple / TownCenter / WatchTower / Wall_FirstAge` 等 glb **只在 `tools/inspect_assets.gd` 里被引用，局内 0 使用** |
| 光照 | 程序化天空 + 平行光 + 雾 + Bloom + Filmic；**GL Compatibility，无 SSAO/SSR**（`arena_look.gd:27-34`） |
| 移动端 | 3D 渲染分辨率 0.72×；阴影距离 36m；草 6000；地形投影关闭（`arena_look.gd` + `project.godot`） |
| 环境粒子 | 全场 **36 个**上浮光点（`arena.gd:4646`） |

### 5.2 王者基准

- 王者峡谷是**手工场景**：三条路、河道、野区台地、高地、悬崖、入口、草丛、遗迹，每个区域有独立的环境叙事和配色。
- 有**高度层次**：河岸、台地、高地、悬崖，不只是视觉，也影响技能与视野。
- 有**植被层次**：草、灌木、树、藤蔓、水生植物、落叶/萤火/飞鸟。
- 有**光照与后期**：方向光、环境光、雾、Bloom、色彩分级、局部光晕、阴影层次。
- 建筑与地形**一体化**：塔基、泉水、野区围栏、桥头都不是"放上去的模型"，而是长在地形里。

### 5.3 差距拆解

| 层 | 差距 | 具体表现 |
| --- | --- | --- |
| UI | 小地图是程序化色块（`minimap.gd:319`），没有地形美术 | 小地图能读，但不像王者那种"缩小的峡谷" |
| 外在形象 | 可玩区严格平地 | 俯视下缺少高低差、遮挡、层次；所有战斗都发生在同一张平面 |
| 外在形象 | 全图只有草/路/石三种质感 | 河道、野区、高地、基地的"区域感"主要靠色偏和圆盘，不靠地貌 |
| 模型 | 贴图四套复用；树被移除；环境建筑全未使用 | 场景干净但空；王者峡谷的"叙事道具"（旗、灯笼、残垣、兽骨）为 0 |
| 特效 | 水面/草/雾有动效，但环境生命感弱 | 只有 36 个光点；没有飞鸟、萤火、落叶、鱼、瀑布、水面倒影 |
| 光照 | GL Compatibility，无 SSAO/SSR/体积光 | 接触阴影靠地形自投影；石头/塔/角色与地面贴合感弱 |
| 破坏 | 塔被摧毁后 `root.visible = false`（`arena.gd:3361-3365`） | 塔直接消失，没有倒塌、扬尘、残骸；王者有完整的摧毁演出与废墟 |

### 5.4 补法

- **P0（1 周）**：塔摧毁改成"倒塌 + 扬尘 + 残留基座"；基地水晶摧毁演出；补基地旗帜/灯笼/石阶等 5–8 个低矮道具。
- **P1（2–4 周）**：河岸加芦苇/碎石/浅滩泡沫；野区加兽骨、残柱、藤蔓；墙外边缘加低模树影；环境粒子从 36 提到 200–400（移动端分级）。
- **P1**：地表 shader 加"大尺度色斑/湿度/踩踏痕"，打破四套贴图的重复感。
- **P2**：可玩区引入**视觉台地**（不影响碰撞/寻路，只做高差与台阶），或至少让野区地面比兵线低 0.2–0.4m，形成"下沉野区"的层次。
- **P2**：如果目标真的是"王者级"，需要换 Forward+/Mobile 渲染器，开 SSAO、体积雾、屏幕空间反射；这是引擎级决策，不是美术能单独补的。

## 6. 城墙

### 6.1 现状（证据）

| 项 | 现状 |
| --- | --- |
| 野区墙 | 砌石基座 `BoxMesh`（厚 1.6m、高 1.25m）+ 沿墙铺 `Rock.glb` 岩脊（1.55–2.45m）+ 墙脚乱石 + 墙端露头（`arena.gd:2509`） |
| 边界墙 | 2.0m 砌石基座 + 岩脊 + 四角岩簇，内表面与 `MapData.BOUNDS` 重合（`arena.gd:2798`） |
| BUFF 围栏 | 折线围出"不规则窝"，顶点半径 3.6–6.75m，开口朝己方基地（`map_layout.gd:82`） |
| 岩石模型 | **单块 `Rock.glb`，仅 162 三角面**；靠缩放/旋转/位置随机化 |
| 材质 | `cliff_side` 的 Diffuse/Normal/Rough/AO + 自定义 `rock_wall.gdshader`：去饱和、砖缝、苔藓、脊顶压暗（`arena_look.gd:112`） |
| 实际观感 | 灰色岩块一排排在砖基座上，块与块之间轮廓相似；墙高约 2–2.5m；俯视更像"石篱笆" |
| 碰撞 | 视觉厚度与碰撞厚度同源，`test_jungle_walls` 等测试守着"不能挡路/不能盖营地" |

### 6.2 王者基准

- 野区墙是**自然山体**：高差大、岩层有走向、顶部有植被、墙脚有碎石坡、局部有洞口/藤蔓/水痕。
- 边界是**悬崖/山脊**，不是一圈等高的城墙；有远近层次和空气透视。
- 墙体与地面、草丛、树木、光影**一体化**，不是"石头模型摆在草地上"。

### 6.3 差距拆解

| 层 | 差距 | 具体表现 |
| --- | --- | --- |
| UI | 碰撞线与视觉同源（做得好） | 但小地图上墙的呈现弱，玩家很难从 UI 读出"哪里能穿、哪里是死路" |
| 外在形象 | **高度不够**：2–2.5m 在俯视下读成"篱笆" | 王者野区墙通常有明显高差，能形成"峡谷"的包裹感 |
| 外在形象 | **重复**：一块 162 面 Rock 反复铺 | 放大截图能看到相同轮廓的石头反复出现；墙顶是一条"石头花边" |
| 外在形象 | **材质语言冲突**：野区应该是自然岩壁，但基座是整齐砖缝 | 近看像城墙，远看像乱石堆，两种语言都不彻底 |
| 模型 | 无岩层/洞口/悬挑/植被模块 | 没有"山"的结构，只有"石块"的堆叠 |
| 特效 | 全静态 | 没有落石、尘土、藤蔓摆动、水痕、雾气贴地 |

### 6.4 补法

- **P0（3–5 天）**：增加 3–4 种岩石变体（不同轮廓/长宽比/棱角），打破重复；墙顶/墙脚加草丛和藤蔓；墙脚加碎石坡。
- **P0**：把野区墙和边界墙的材质语言分开——野区用自然岩壁（去掉砖缝），边界保留砌石/城防感。
- **P1（1–2 周）**：局部抬高到 3.5–5m（只在不可走区域），配合相机遮挡淡出；增加洞口/缺口作为野区入口地标。
- **P1**：给墙做"岩层走向"shader（沿世界 Y 的水平层理 + 噪声扰动），比换模型便宜，能显著去掉"灰色纸盒"感。
- **注意**：任何高度/体量变化都必须过 `test_jungle_walls` / `test_boundary_walls`，视觉不能压进可走区，也不能挡住血条。

- 结算有 **MVP 展示、英雄立绘/模型、数据条、点赞**。
- 选人有 **3D 模型展示、皮肤切换、动作/技能预览**。

### 7.3 差距拆解

| 层 | 差距 | 具体表现 |
| --- | --- | --- |
| 信息架构 | 当前 HUD 信息齐全，但"装备/Buff"缺失 | 玩家看不到自己出了什么、身上有什么增益 |

| 图标 | 普攻键所有英雄都是剑 | 星璃/翎羽按"剑"攻击，视觉上不成立 |
| 装饰 | 全部是纯色圆角面板，无 9-slice 花纹/材质 | 干净、现代，但没有王者的"史诗感/东方幻想感" |
| 小地图 | 程序化色块；野怪是圆点；无地形美术 | 能读，但不像"王者峡谷" |
| 播报 | 纯文字 | 缺少头像、横幅、连杀演出 |
| 结算 | 纯文字 | 缺少 MVP 和展示欲 |
| 选人 | 2D 卡片 + 视频 | 与局内模型割裂；无皮肤/3D |

### 7.4 补法（性价比最高的 UI 改造）

1. **17 张技能图标 + 5 张普攻图标**（P0，3–5 天）：这是玩家每秒都会看到的界面，收益最大。
2. **Buff/Debuff 图标 + 装备格**（P0，2–3 天）：补齐英雄面板。
3. **击杀横幅加英雄头像 + 连杀纹章**（P0，2 天）。
4. **商店详情卡 + 品质框 + 分类页签**（P0，1 周）。
5. **小地图地形美术底图**（P1，3–5 天）：一张手绘/渲染的峡谷底图，叠在程序化绘制下面。
6. **MVP 结算页**（P1，3–5 天）：英雄立绘 + 数据 + 点赞。
7. **9-slice 金边/云纹面板**（P1，1 周）：把纯色 StyleBox 换成带纹理的边框，整体质感提升一个档。

## 8. 技能与战斗特效

### 8.1 现状（证据）

| 项 | 现状 |
| --- | --- |
| 配方 | `skill_fx.gd` 为 17 种 `kind` 定义"环 + 粒子 + 抛射物 + 拖尾 + 光束 + 震屏 + 顿帧" |
| 形状 | 环 = `TorusMesh`；粒子 = 24 个 `GPUParticles3D` + 方片；弹道 = 球；光束 = 圆柱；刀光 = 程序化新月面片（`arena.gd:4200-4317`） |

| 颜色 | 每个英雄一个谱系色（苍刃橙 / 星璃紫 / 铁壁青 / 翎羽绿 / 墨鸦粉） |
| 打击感 | 已做：顿帧、震屏、飘字、受击粒子、暴击变白（`arena.gd:4047`） |
| 残留 | **无**：技能结束后地面没有痕迹 |
| 受击 | 英雄播放 `Hit_Chest`；野怪程序化形态**无受击动作** |
| 护盾 | 只有血条上的护盾段，**没有护盾泡** |
| 死亡 | 英雄 `Death01`；小兵 `Death_A`；程序化野怪前倒；**无溶解/灵魂/残骸** |
| 塔摧毁 | 爆炸 + 顿帧，然后塔直接消失（`arena.gd:3880`） |
| 环境 | 36 个上浮光点（`arena.gd:4646`） |

### 8.2 王者基准

- 每个技能有**独立特效设计**：贴图序列帧、模型、拖尾、地面法阵、屏幕特效、镜头运动、音效，全部为一个技能定制。
- 有**前摇预警**（地面圈/箭头/蓄力光）、**命中反馈**（闪白、击退、硬直、屏幕震动）、**残留**（灼烧地面、冰霜、法阵）。
- 有**元素语言**：火、冰、雷、暗影、星辰，各有颜色、形状、粒子、屏幕效果。
- 有**护盾泡、霸体光、buff 光环、debuff 标记**。
- 有**击杀/团灭/推塔**的大场面演出。

### 8.3 差距拆解

| 层 | 差距 | 具体表现 |
| --- | --- | --- |
| 形状语言 | 所有特效都是环/球/方片 | 苍刃 R（跳斩）和星璃 R（陨石）都是"大环 + 粒子 + 震屏"，只是颜色不同 |
| 资产 | 0 张特效贴图 | 没有火焰、烟雾、闪电、星光、刀光纹理；粒子是纯色方片 |
| 技能签名 | 17 个技能 -> 5 类配方 | 同族技能视觉上几乎一样，玩家分不清是谁放了什么 |
| 前摇/预警 | 有技能指示器（HUD），但 3D 场景没有预警圈/蓄力光 | 被技能命中前缺少"要躲"的视觉信号 |
| 命中反馈 | 有飘字/粒子/震屏/顿帧，但**无模型闪白**、无击退 | 打上去像"打空气"，尤其野怪不缩身 |
| 状态 | 无护盾泡、无 Buff 光环、无 Debuff 标记 | 红/蓝 BUFF、护盾、减速在角色身上都看不见 |
| 残留 | 无地面痕迹 | 技能放完地面立刻干净，缺少"战斗发生过"的痕迹 |
| 死亡 | 无溶解/残骸 | 野怪前倒后消失；塔直接消失 |

### 8.4 补法

- **P0（3–5 天）**：加 4–6 张通用特效贴图（噪声、火花、烟雾、法阵、刀光渐变），把方片粒子换成带贴图的 billboard；受击加**模型闪白**；护盾加**半透明球泡**。
- **P0（2–3 天）**：每个 `kind` 至少改一处形状/节奏（例如 burst 加延迟二次爆、line 加宽度渐变、arrow 加拖尾丝带），让同族技能有差异。
- **P1（2–3 周）**：给每个技能做独立配方（颜色 + 贴图 + 地面法阵 + 命中残留）；加前摇预警圈；加技能命中后的地面灼烧/冰霜/星尘 decal。
- **P1**：塔摧毁改"倒塌 + 扬尘 + 残骸"；首领死亡加慢动作 + 全屏暗角。
- **P2**：屏幕空间效果（径向模糊、色差、冲击波扭曲）；这需要更高渲染管线或屏幕纹理，GL Compatibility 下要评估。

## 9. 根因：为什么视觉会变成这样

| 根因 | 说明 | 影响 |
| --- | --- | --- |
| **2D/3D 两条生产线** | 立绘/视频/物品图标是 AI 生成的写实国风；3D 是程序化低模 + 第三方通用包 | 选人和对局像两个游戏 |
| **没有美术资产标准** | 没有 art bible、没有统一色板/描边/材质规范；每类资产各自为战 | 单看可以，合在一起不协调 |
| **第三方资产包** | 身体、小兵、狼、岩石、动作库来自通用低模包；glb 无 `copyright/license` 字段 | 风格不可控，商用有合规风险（见差距文档 §5.1） |
| **没有动画/绑定产能** | 只有 UAL retarget；没有专属动作、面部、布料、头发 | 英雄/野怪"动起来像人偶" |
| **渲染管线天花板** | GL Compatibility；无 SSAO/SSR/体积光；移动端 3D 0.72×、阴影 36m | 材质和光照上限被锁死，追王者写实不现实 |
| **镜头距离** | zoom 21，英雄占屏高 7% | 高模/高分辨率贴图的收益极低；剪影和配色才是第一优先级 |
| **内容体量** | 5 英雄 / 8 装备 / 7 野怪形态 | 不是打磨问题，是产能问题；王者是百级内容 |
| **视觉反馈链不完整** | 有飘字/顿帧/震屏，但缺闪白、残留、状态 aura、摧毁演出 | "打得动"有了，"打得爽/看得懂"还差一层 |

## 10. 建议路线图

> 估算按"1 名开发 + 可外包 2D/3D"计；只有 1 名开发时，P1 的时间要乘 2–3。

### P0 · 先消除"出戏点"（2–3 周）

目标：不换模型，也能让对局"看起来是一个完整的产品"。

1. **17 张技能图标 + 5 张普攻图标 + Buff/Debuff 图标**（2D，收益最高）。
2. **英雄剪影/配色对齐立绘**：调整 5 个英雄的体型、肩宽、武器比例、主色；把队伍染色从"整体染"改成"描边/肩甲/武器发光"。
3. **野怪反馈**：攻击前倾、受击缩身、闪白、死亡溶解；BUFF 持续 aura；小兵按类型加配件。
4. **塔/水晶摧毁演出**：倒塌 + 扬尘 + 残骸；不再直接消失。
5. **城墙变体**：3–4 种岩石轮廓 + 墙脚草/藤蔓 + 野区/边界材质分离。
6. **特效底子**：4–6 张通用贴图、护盾泡、模型闪白、地面残留。
7. **商店详情卡 + 品质框 + 分类页签 + 英雄装备格**。

### P1 · 建立"可持续的视觉生产线"（2–3 个月）

1. **5 个英雄定制模型**：独特剪影、对齐立绘、布料/头发骨骼、每英雄 3–4 个专属动作。
2. **每个技能独立特效**：贴图序列 + 地面法阵 + 命中残留 + 前摇预警。
3. **首领演出**：出场镜头、咆哮、技能预警、阶段变化、死亡慢动作；暴君/主宰换骨架。
4. **场景叙事**：河岸芦苇、野区兽骨/残柱/藤蔓、基地旗帜/灯笼、墙外树影、环境粒子分级。
5. **3D 选人展示**：模型旋转、待机动作、技能预览、皮肤页（先留接口）。
6. **MVP 结算页 + 击杀横幅头像 + 小地图地形底图**。
7. **UI 9-slice 金边/云纹套件**：把纯色面板换成有材质的边框。

### P2 · 追平"内容与质感"（3–6 个月，需要团队）

1. 皮肤系统（换模型/换色/换特效/换语音）。
2. 英雄 20+、装备 50+、野怪 20+、场景 2–3 张。
3. 高配渲染管线（Forward+/Mobile，SSAO、体积雾、屏幕空间反射）。
4. 语音/口型/界面动效/社交展示。
5. 视觉回归截图库 + 自动对比（防止"改了材质，另一个场景崩了"）。

## 11. 验收标准（视觉）

视觉改动也必须过仓库的四道关，另加视觉专项：

| 关 | 内容 |
| --- | --- |
| 机器关 | `godot --headless --path godot --script res://tests/run_tests.gd` 末行 `FAILED: 0`，并扫 `ERROR:` 行 |
| 视觉关 | 桌面 1600×900 + 移动端竖屏各截图；21m 默认镜头下能读出：英雄/小兵/野怪/塔/墙 的剪影与阵营 |
| 图标关 | 17 个技能图标两两不同；5 个普攻图标与英雄武器一致；无空白/占位图 |
| 状态关 | 红/蓝 BUFF、护盾、减速、回血在角色身上有可见表现；塔摧毁后有残骸 |
| 性能关 | 桌面 ≥60fps、移动端 ≥30fps（现有基线）；粒子/贴图不破坏池与 draw call 纪律 |
| 一致性关 | 立绘、模型、技能特效、UI 主色属于同一角色/同一世界观；截图并排对比无"换了游戏"感 |

可用工具（都是现成的）：

```cmd
godot --headless --path godot --script res://tests/run_tests.gd
godot --path godot --script res://tools/hero_gallery.gd
godot --path godot --script res://tools/monster_gallery.gd
godot --path godot --script res://tools/ui_shot.gd
godot --path godot --script res://tools/mobile_shot.gd
godot --path godot --script res://tools/arena_shot.gd
godot --path godot --script res://tools/perf_check.gd
```

## 附录 C · 一句话给决策者

**如果只能做三件事**：

1. 把 17 个技能图标和 5 个普攻图标画出来（2D，1 周）；
2. 把 5 个英雄的剪影和主色对齐立绘（2D/3D 调参，1 周）；
3. 给野怪加"受击缩身 + 闪白 + 死亡溶解"，给塔加"倒塌 + 残骸"（程序化，1 周）。

这三件事做完，对局的"完整度"会从"技术 Demo"跳到"有美术的游戏"，但**不会**让它变成王者荣耀。要追王者，需要的是模型、动画、贴图、特效、UI 五条生产线同时扩容——那是团队和周期问题，不是这一轮打磨能解决的。
